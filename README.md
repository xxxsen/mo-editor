# 心灵终结规则编辑器

一个本地运行的心灵终结规则编辑器，提供 Windows 桌面版和浏览器版。初始展示的数据完全虚构，不包含心灵终结或游戏本体的资源。

## Windows 桌面版

直接运行 `dist/MentalOmegaEditor.exe` 即可使用。Windows 需要 WebView2 运行时。

启动桌面程序后选择游戏目录，例如 `D:\MentalOmega`。程序会记住最近打开的目录；修改后点击「保存」或按 `Ctrl+S`，直接写回对应 INI 文件。保存前会备份被覆盖的文件；如果游戏目录中的文件在打开后被其他程序修改，保存会停止并保留当前编辑内容。

启动时窗口会按首个对象的内容调整高度，最大不超过所在屏幕的可用高度；屏幕空间不足时详情区域仍可滚动。用户手动调整窗口后，程序不会再自动改变窗口尺寸。

「历史版本」列出每次保存或恢复前涉及的文件，恢复时只还原记录中列出的文件，并再次备份当前文件。「另存为」可将当前主规则及已加载的 include 文件按相对路径输出到另一个目录，原项目的未保存修改会继续保留。

备份位于 `%LOCALAPPDATA%\local.mentalomega.ruleseditor\backups`，每个游戏目录独立保存。首次从 MIX 读取的规则会保存为目录中的独立 INI，不会修改 MIX；恢复到原先没有独立文件的状态时会移除该次生成的文件。未解析的 include、循环引用及不支持的继承会阻止直接保存，先解决加载提示后再保存。

从源码构建 Windows 桌面版需要 Node.js、Rust MSVC 工具链、Visual Studio C++ Build Tools 和 WebView2。安装依赖后在 Windows 的项目目录中运行：

```powershell
npm install
npm run desktop:dev
```

生成免安装程序：

```powershell
npm run desktop:build
```

构建后生成免安装程序 `dist/MentalOmegaEditor.exe`；Tauri 原始输出位于 `src-tauri/target/release/mental-omega-editor.exe`。具体工具链要求见 [Tauri 文档](https://v2.tauri.app/start/prerequisites/)。

开发构建使用固定文件名。将包含发布工作流的提交推送到 GitHub 后，推送标签会触发 GitHub Actions：在 Windows 上运行测试、构建免安装版，并创建对应的 GitHub Release。例如：

```sh
git tag v1.0.0
git push origin v1.0.0
```

Release 附件名为 `MentalOmegaEditor-v1.0.0.exe`；文件名中的版本来自标签，不改变项目内部版本号。标签中不适合文件名的字符会替换为 `-`。工作流使用 GitHub 自动提供的令牌，需要仓库设置允许 Actions 创建 Release。

## 浏览器版启动

在项目目录下启动本地静态服务器：

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

Windows 如果已安装 Python，可以使用：

```bat
py -m http.server 4173 --bind 127.0.0.1
```

打开 <http://127.0.0.1:4173/>。推荐使用最新版 Chrome 或 Edge；文件夹导入需要支持目录选择的浏览器。无需安装前端依赖，也不需要联网。

## 使用

1. 点击「导入文件夹」选择游戏目录，或通过「打开文件」一起选择 `rulesmo.ini`、`ra2md.csf` 及相关 MIX 文件。文件夹应保留 `[#include]` 使用的相对路径。
2. 编辑器优先读取目录根部的 `rulesmo.ini`；如果不存在，就从已选 MIX 中查找并读取。页面右上角和属性来源会显示实际使用的文件；点击主文件名称可在可搜索的列表中切换，缺少 include 文件或检测到循环引用时会提示。
3. 在左侧选择步兵、载具、飞机、建筑、超级武器、武器、投射物或弹头，搜索中文名、英文名或代码，也可按所属国家筛选。左侧搜索还会列出匹配的全局参数，可用字段名或已提供的中文名称直接定位，例如 `RepairSell` 或「建筑自动维修」。单位的国家、装甲和建造前置可以搜索选择；弹头的基础装甲伤害修正和扩展装甲修正可以逐项编辑。
4. 「全局配置」提供常规设置、战斗、电脑、难度、国家和阵营等规则段；可在段内搜索全部已定义字段，也可添加字段。「所有规则段」可浏览其他规则段，逗号分隔的值可按原顺序分项编辑。
5. 「超级武器」读取 `[SuperWeaponTypes]` 中的注册项，支持修改充能、费用、效果与限制等参数；建筑和其他提供对象中的超级武器可通过选择器调整，关联关系可双向查看。未定义的参数显示为空，具体默认值和效果取决于武器类型及游戏引擎。
6. 桌面版点击「保存」写回并备份；也可以点击「另存为」输出到其他目录。浏览器版通过「查看修改」逐个下载已修改的文件，再根据路径提示自行放置。

对象列表的「新增」和对象详情的「复制并新建」支持步兵、载具、飞机、建筑、武器、投射物、弹头、超级武器及普通规则段。可搜索模板或空白创建，预览规则段、类型登记及保留的引用后加入当前修改；还需点击「保存」才会写入文件。游戏对象的 ID 限制为 24 个字符，建议 ID 会自动缩短；普通规则段不受此限制。类型登记追加到已有列表末尾；没有对应列表时会创建列表。对于投射物，该列表用于编辑器管理，游戏效果仍需武器引用。

复制只创建所选对象，武器、弹头、投射物及其他引用默认继续共享。可以逐个复制这些关联对象，再通过字段旁的「选择」替换引用；复制前已编辑但未保存的值也会保留。复制单位时，未指定 `Image` 会自动复用模板图像；`UIName` 沿用模板，不会创建新的中文字符串或美术资源。空白对象需自行补充游戏需要的属性，单位能否建造和超级武器能否使用还取决于相应规则。

从武器、弹头或超级武器字段的「查看」进入关联对象后，左侧列表会定位到该对象。可使用顶部的返回、前进按钮、鼠标侧键或 `Alt+←` / `Alt+→`，也可点击详情顶部的访问路径。返回会恢复当时的搜索、筛选、页签和滚动位置，并保留未保存的规则修改。切换项目或主文件后，浏览记录会清空；桌面版的「历史版本」是文件备份，与浏览记录分开。

武器和弹头的基础属性页显示根据已加载规则识别出的引用数量，点击「查看引用」可列出使用者；特殊规则和未加载的文件可能包含其他引用。字段旁的「查看」打开目标规则段，直接编辑字段值则会更改引用。全局默认的炸弹弹头标为「查看默认」，查看时不会写入覆盖值。

已收录的规则字段显示为「中文名 / 规则字段名」，鼠标悬停可查看作用说明；未确认作用的字段保留原始代码，不推测含义。

「全部属性」中的「添加字段」提供可搜索的字段目录，并优先列出当前项目同类对象使用过的字段；同类已用但未收录的字段和适用类型待确认的字段会分别标识。也可直接输入自定义字段名。值留空时仅在界面添加待编辑项，不会填入默认值或修改文件；填写值后才加入待保存修改。不同游戏、扩展版本及对象逻辑支持的字段并不完全相同，目录不能保证穷尽所有字段或保证每个字段都生效。

单位的「基础属性」提供老兵与精英能力多选。移动类型、移动区域、对象及建筑分类、生产类别、状态标记、超级武器目标与所属方范围，以及已确认的常见开关也可从中文选项中选择；「全部属性」保留原始输入和选择入口。未识别的现有代码会列出并保留，除非手动取消或替换；Ares 能力须由游戏所用扩展支持。

武器的 `Warhead` 是命中弹头，`IvanBomb.Warhead` 是附着炸弹爆炸时使用的弹头，两者可分别编辑和查看关联。命中弹头需要启用 `IvanBomb=yes`，炸弹效果才会生效；未单独设置或留空时，编辑器会根据已加载的 `[CombatDamage]IvanWarhead` 显示全局默认值及其来源，不会把默认值写入武器规则。具体规则参见 [Ares 炸弹文档](https://ares-developers.github.io/Ares-docs/new/weapons/ivanbombs.html)。

投射物根据 `[Projectiles]` 列表和已识别武器的 `Projectile` 引用收集；空爆及弹片的子武器会继续解析。武器的投射物可直接输入或搜索选择，并可跳转到投射物属性、查看使用它的武器。修改共享投射物会影响使用它的武器；未加载或特殊逻辑中的引用可能没有列出。

浏览器版导入的文件和修改保存在当前页面的内存中，刷新前请先导出需要保留的修改。有修改时浏览器会在离开页面前提示。桌面版从单个文件导入的项目可浏览和下载；直接保存需要先选择游戏目录。

当所选文件包含 `ra2md.csf` 时，名称优先使用 `UIName` 对应的本地字符串，否则回退到 INI 内的 `Name` 或代码。找到相应的 PCX 资源后，单位图标从美术配置读取，超级武器图标从其 `SidebarPCX` 字段读取。相同武器的使用者根据主副武器、驻军武器和编号武器字段查找，并不覆盖所有扩展逻辑。

## 格式与限制

- 未改动的文件按原始字节输出；修改已有属性时保留其所在行的其他内容、注释、顺序及原始换行。修改会写入已加载文件中最后一个定义该属性的位置；添加新属性会写入最后一个同名区块。
- 国家、装甲及建造条件的选项根据当前规则生成；未登记的原有代码会保留。基础装甲伤害修正按游戏的 11 类固定顺序编辑，未设置的项目不会自动补值。
- 支持 UTF-8 和常见 GBK 文件的读取。为了避免损坏原始编码，GBK 文件和无法判断编码的纯 ASCII 文件目前只允许写入 ASCII 字符；UTF-16 文件暂不支持。
- 按 Ares 的 `[#include]` 深度优先顺序解析导入的文件；未找到独立文件时，会在 MIX 中查找不带子目录的 include。不支持 Phobos 的 INI 包含机制或 `$Inherits` 继承，遇到未找到的引用或 `$Inherits` 会提示。根据不同游戏、扩展、客户端和地图的加载方式，实际生效值还可能受到其他文件覆盖。
- 目前可以从未加密的 MIX 索引读取主规则、美术配置和 PCX 图标；暂不支持加密索引、嵌套 MIX、SHP 图标或模型动画。资源只在内存中按需读取，不会解包到磁盘。
- 桌面版的「保存」会修改所选游戏目录，自动备份覆盖前的文件；「另存为」写入另选目录。浏览器版仅下载文件。程序不启动游戏，也不保证某个版本的客户端会加载生成的文件，仍需在游戏中验证。

## 开发验证

字段对照表维护在 `src/field-metadata.js`，按单位、武器、投射物、弹头、超级武器、国家和全局规则段分组。每项依次填写 `[中文名, 作用说明, 可选搜索别名, 可选常显提示]`；同名字段按对象类型或规则段匹配。编号武器和炮塔、加特林阶段、连发间隔、各阵营逃生驾驶员、`Versus.<装甲>` 和带国家或飞机编号的空投字段由同一文件内的规则处理。字段含义主要依据原版 `rulesmd.ini` 注释以及 [Ares 文档](https://ares-developers.github.io/Ares-docs/)；不同版本对扩展字段的支持可能有差异。

固定选项和字段适用范围集中维护在 `src/enum-options.js`；新增选项应确认引擎版本、单选或多选语义及未知值保留行为。`tests/enum-choice-check.html` 覆盖选项选择、取消、未知值、中文搜索及导出。

可添加字段目录由 `src/field-catalog.js` 汇总现有字段字典和当前项目的同类对象字段；编号类字段支持按规则手动输入，扩展装甲字段会根据当前项目生成。`tests/field-catalog-check.html` 覆盖缺失字段搜索、空白待编辑项、结构化选项和导出。

```sh
npm test
```

浏览器端的导入、编辑、关联与导出检查位于 `tests/browser-check.html`；长列表滚动、焦点及连续操作检查位于 `tests/scroll-check.html`；资源解析和图标显示检查位于 `tests/resource-check.html`；规则来源优先级检查位于 `tests/rules-source-check.html`；全局配置、结构化字段和固定高度检查位于 `tests/structured-check.html`；跨规则段搜索检查位于 `tests/global-search-check.html`；中文输入及超级武器检查位于 `tests/superweapon-ime-check.html`；字段中文名及说明检查位于 `tests/field-metadata-check.html`；驻军武器及其关联检查位于 `tests/garrison-weapons-check.html`；武器的直接命中与附着炸弹弹头检查位于 `tests/weapon-warheads-check.html`。启动本地服务器后可访问这些页面运行。

`tests/desktop-check.html` 模拟桌面文件接口，覆盖保存、冲突、恢复、另存为和 MIX include；`tests/navigation-check.html` 检查关联跳转和浏览记录；`tests/projectile-check.html`、`tests/object-creation-check.html` 与 `tests/main-file-picker-check.html` 检查投射物编辑、对象新增和主文件选择；`src-tauri/src/store.rs` 中的 Rust 测试使用临时目录验证真实文件写入、备份和中断恢复。
